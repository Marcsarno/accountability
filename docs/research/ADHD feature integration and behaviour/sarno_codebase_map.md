## 1. Rules, pipeline and conventions a feature must follow (CLAUDE.md, README, ROUND-NOTES, SETUP-SUPABASE, planning/)

### Takeaway
Sarno is governed by a long, trap-driven `CLAUDE.md` (1,210 lines) with an architecture contract (generated UI, one big logic class, seed-derived state shapes), a mandatory verification pipeline, and a strong review culture (no deploys/pushes/SQL/keys, flag decisions, name the test behind any claim). Each "round" is scoped by a planning document, built in phases, and recorded in `ROUND-NOTES.md` with changed files and the verification table. The documented baseline numbers are stale at the current commit, and `tokens.py` is no longer idempotent.

## 2. UI generation: how screens, sheets, tabs and navigation are added; can a separate module be added?

### Takeaway
All UI lives in one template (`tools/proto/markup.html`, UI body lines 9594–10944 after ~9,600 lines of embedded CSS/fonts) converted mechanically into one `AppView({ v })` component. Screens are `sc-if` blocks keyed on `tab`; sheets are `sc-if` blocks on `xxxOpen` flags with a scrim + `fh-sheet` body; nav is a hand-laid row in the template. Bindings are plain properties/closures on the object returned by `renderVals()`. The only hand-written React outside the generator is `src/main.jsx` chrome (banners, crash guard, rotate lock); the only separate logic module is `src/smartadd.js` (pure contract shared with `api/`). A separate component is technically possible via `main.jsx`, but has no precedent for a full screen and would bypass `verify.py`, the binding-completeness invariants, `tokens.py`, and smoke's tab walk.

### Inferences
- Adding a "Now" screen the house way = new `tab` value (e.g. `'now'`), a new `sc-if {{ isNow }}` screen block in markup.html, nav or entry-point changes in the L9966 nav line, `isNow/goNow` vals in `renderVals()` (or a spread `...this.nowVals()`), deep-link support via `DEEP_TABS`, and new sheet flags in `_allClosed()`. Snooze/make-smaller/routine-player sheets each become `sc-if` + `fh-sheet` blocks.
- Logic can be partially modularised following the `smartadd.js` precedent: a pure, framework-free module (ladder schedule, wording rotation, snooze-to-clock math, first-step/size heuristics) imported by `logic.js` and by the server function, with its own node test file. That avoids fighting the generator for logic, but the visible UI still has to go through markup.html → convert.py unless a deliberate exception is made.
- A self-contained React component mounted from `main.jsx` (like `SyncBanner`) is possible, but it would sit outside `verify.py`, the sc-if/sc-for binding-completeness invariants, smoke's jsdom walk (smoke.entry.jsx does not mount main.jsx chrome), and `tokens.py`'s colour discipline — so it would need its own tests and a recorded exception in CLAUDE.md. There is no precedent for a full screen this way.
- A focus countdown needs per-second updates; the app's only clock is the 60 s `tick()` plus re-render, so a countdown would need either its own timer (new effectful code path; tick() is described as "the one place that is allowed to have effects on a schedule") or a hand-written component.

## 3. Data: migrations, personal_todos schema/RLS, is_household_manager, client read/write, offline/caching

### Takeaway
Seven sequential, hand-run, idempotent SQL migrations. `personal_todos` (0002) is the model private table: per-row RLS forced, all four policies `user_id = auth.uid() AND is_household_manager(household_id)`, server-stamped `updated_at`, explicit grants, no time-of-day column. The client reads it by a full-list GET on a 10 s poll + foreground + reconnect (no realtime), writes optimistically with visible rollback, and caches per-uid in localStorage; there is no durable offline write queue for reminders.

### Inferences
**What a skeleton must match to merge cheaply**
1. Language/format: plain ES modules (`"type": "module"`), no TypeScript, no new runtime deps (Sarno ships with only react, react-dom, web-push — [package.json L21-25](/home/user/sarno/SarnoPWA/package.json)); tests as plain `node` scripts with the `ok(name, cond)` pattern, runnable under `--import ./tools/fixed-clock.mjs`.
2. Logic as a pure module (e.g. `src/focus.js`): no React, no fetch, no Date.now() without injection (`nowMin` injection is the house pattern — [ROUND-NOTES.md L277-281](/home/user/sarno/SarnoPWA/ROUND-NOTES.md)), importable by both `logic.js` and an `api/*.js` function.
3. Data: SQL written as a sequential `0008_*.sql` in Sarno's migration style (idempotent `if not exists` / `drop policy if exists`, RLS enabled + FORCED, `to authenticated` policies with USING + WITH CHECK, explicit `revoke all … from anon, authenticated` + grants, comment header with WHY/SECURITY IDENTITY/ACCESS TIER, verification SQL in comments) — modelled on [0002](/home/user/sarno/SarnoPWA/supabase/migrations/0002_personal_todos.sql) and [0007](/home/user/sarno/SarnoPWA/supabase/migrations/0007_sitter_availability.sql).
4. Server: same shape as `api/notify.js` — GoTrue-verified caller, `dbAsUser` for caller-scoped reads, `dbAsAdmin` only with a written, column-scoped grant, secrets from `process.env`, never `VITE_`, error bodies as fixed enums with `retryable` booleans.
5. UI: state shapes and view-model functions that return flat, fully-defined objects (every field the template binds defined in every reachable state; booleans paired as `x`/`notX` because the DSL has no `!`), so `nowVals()` can be spread into `renderVals()` and the markup written against it.

**What will make merging painful**
- Any React component tree, hooks, CSS files or SVG: must be rewritten into markup.html's inline-style DSL, or kept as an exception outside verify/smoke/tokens.
- Per-second timers (focus countdown) — no precedent; 60 s tick is the only clock.
- Server scheduler reading private reminders: conflicts with 0004's principle and privacy test S (`service_role holds nothing on personal_todos`), and requires adding a cron config file (`vercel.json`) that does not exist today, or pg_cron/pg_net that no migration uses.
